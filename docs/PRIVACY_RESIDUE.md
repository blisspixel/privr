# Privacy residue and documented vendor erasure specification

## Purpose and scope

This document specifies the privacy threat model, artifact catalogue, and
remediation architecture for local privacy residue across Windows, macOS, and
Linux.

`privr` evaluates two complementary dimensions of machine privacy posture:

1. **Telemetry in transit:** whether operating systems, runtimes, and browsers
   are configured to transmit diagnostics, telemetry, and behavioral analytics
   to vendor networks. Evaluated through `check`, `explain`, `plan`, and
   `apply` with exact rollback.
2. **Privacy residue at rest:** sensitive local forensic artifacts generated by
   operating systems, browsers, and developer tools that persist unencrypted
   on disk after original files are deleted, closed, or dismounted. Managed
   through the `purge` verb specified in `docs/CLI.md` and constrained by
   decision 13 in `docs/DECISIONS.md`.

This specification defines the cross-platform taxonomy of privacy residue,
documents primary vendor sources, identifies authoritative vendor erasure
mechanisms, and enforces strict non-reversibility reporting.

## Threat model: data-at-rest exposure

Conventional privacy tools focus almost exclusively on active network
telemetry. In digital forensics and incident response (DFIR), local forensic
residue is the primary mechanism through which past activity, deleted content,
unencrypted credentials, and communication records are reconstructed.

Local privacy residue presents four distinct threat vectors:

1. **Physical or secondary-user exposure:** inspection of local storage by an
   unauthorized party or inspection during device resale, seizure, repair, or
   sharing.
2. **Encrypted container leakage:** visual thumbnails and access timestamps of
   files residing on BitLocker, FileVault, or VeraCrypt containers leaked to
   the host drive in cleartext caches.
3. **Volatile memory persistence:** raw process heap and stack state dumped
   during crashes containing plain-text tokens, session cookies, and private
   keys.
4. **Local model and agent retention:** coding assistants and local AI harnesses
   recording unredacted source code, database credentials, and prompt text
   into unbounded local databases.

## Artifact catalogue by platform

### 1. Windows

#### File Explorer thumbnail cache
- **Artifact:** `%LOCALAPPDATA%\Microsoft\Windows\Explorer\thumbcache_*.db`
- **Mechanism:** Windows Explorer automatically extracts and caches scaled
  renderings of images, video frames, and document front pages.
- **Privacy risk:** Thumbnails persist after the original files are deleted,
  including files browsed on removable storage or mounted encrypted volumes.
- **Prevention policy:** `HKCU\Software\Microsoft\Windows\CurrentVersion\Policies\Explorer\NoThumbnailCache = 1`
  or Policy CSP `FileExplorer/TurnOffThumbnailCache`.
- **Documented purge mechanism:** Windows Disk Cleanup API (`cleanmgr.exe` with
  the `Thumbnail Cache` parameter) or registered Explorer shell cache reset.
- **Primary source:** [Microsoft Policy CSP - FileExplorer](https://learn.microsoft.com/windows/client-management/mdm/policy-csp-fileexplorer).

#### Windows push notifications database
- **Artifact:** `%LOCALAPPDATA%\Microsoft\Windows\Notifications\wpndatabase.db`
- **Mechanism:** Windows Push Notification Service (WNS) logs toast notifications
  from installed desktop applications and web browsers into an SQLite database.
- **Privacy risk:** Plain-text message snippets from encrypted messengers
  (Signal, WhatsApp, Telegram), emails, calendar appointments, and two-factor
  authentication codes remain readable in the database and its write-ahead log
  (`wpndatabase.db-wal`).
- **Prevention policy:** Disabling lock screen and desktop notification history.
- **Documented purge mechanism:** Windows Notification Platform database
  reset via service-managed cleanup.
- **Primary source:** [Microsoft WNS documentation](https://learn.microsoft.com/windows/uwp/design/shell/tiles-and-notifications/windows-push-notification-platform).

#### ShellBags
- **Artifact:** Registry keys under `HKCU\Software\Classes\Local Settings\Software\Microsoft\Windows\Shell\BagMRU`
  and `Bags` in `USRCLASS.DAT`.
- **Mechanism:** Explorer records user view settings, window size, icon
  positions, and folder names whenever a directory is opened.
- **Privacy risk:** Retains complete directory paths and access timestamps for
  directories that have been deleted, moved, or opened from external storage.
- **Prevention policy:** Windows exposes no official policy to disable ShellBags
  creation; it is an audit-only forensic artifact.
- **Documented purge mechanism:** Selective removal of user MRU keys in
  `USRCLASS.DAT` under user confirmation.

#### System Resource Usage Monitor (SRUM)
- **Artifact:** `%SystemRoot%\System32\sru\SRUDB.dat`
- **Mechanism:** Background diagnostic service recording hourly application
  runtime, user accounts, and total network egress and ingress per interface.
- **Privacy risk:** Retains a continuous 30-day to 60-day behavioral and network
  consumption timeline of every binary executed on the machine.
- **Classification:** Audit-only. System service required for network usage
  and battery telemetry.

#### Chromium and Edge Crashpad dumps
- **Artifact:** `%LOCALAPPDATA%\Microsoft\Edge\User Data\Crashpad\reports\*.dmp`
  and Google Chrome equivalent.
- **Mechanism:** Crashpad writes full user-mode memory dumps when a browser
  process or render thread crashes.
- **Privacy risk:** Minidumps and full heap dumps contain decrypted DOM state,
  session authentication cookies, and active URLs.
- **Prevention policy:** `SOFTWARE\Policies\Microsoft\Edge\MetricsReportingEnabled = 0`
  stops transmission to Microsoft endpoints.
- **Documented purge mechanism:** Edge and Chrome internal crash history clear
  or removal of orphan `.dmp` files from the Crashpad reports folder.

#### Virtual memory paging file residue
- **Artifact:** `%SystemDrive%\pagefile.sys`
- **Mechanism:** Windows Memory Manager swaps inactive virtual memory pages
  from RAM to disk.
- **Privacy risk:** Memory pages contain unencrypted plaintext passwords,
  decryption keys, session tokens, and documents that persist in physical media
  sectors across system shutdowns.
- **Prevention policy:** `ClearPageFileAtShutdown = 1` under
  `HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\Memory Management`
  or Security Option `Shutdown: Clear virtual memory pagefile`.
- **Primary source:** [Microsoft security policy settings: Shutdown clear virtual memory pagefile](https://learn.microsoft.com/windows/security/threat-protection/security-policy-settings/shutdown-clear-virtual-memory-pagefile).

#### Storage delete notification (TRIM / UNMAP)
- **Artifact:** Unallocated flash memory blocks across physical SSD media.
- **Mechanism:** File system delete notifications inform solid-state drive
  controllers when file sectors are deallocated.
- **Privacy risk:** When delete notifications are disabled (`DisableDeleteNotification = 1`),
  underlying flash cells retain deleted file data indefinitely without
  background wear leveling or physical block erasure.
- **Prevention policy:** `DisableDeleteNotification = 0` under
  `HKLM\SYSTEM\CurrentControlSet\Control\FileSystem`.
- **Primary source:** [Microsoft fsutil behavior documentation](https://learn.microsoft.com/windows-server/administration/windows-commands/fsutil-behavior).

#### Windows Error Reporting (WER) process crash dumps
- **Artifact:** `%LOCALAPPDATA%\CrashDumps\*.dmp` and `%ProgramData%\Microsoft\Windows\WER\`
- **Mechanism:** Windows Error Reporting captures uncompressed process memory
  dumps when desktop applications crash.
- **Privacy risk:** Process heap dumps expose user authentication tokens,
  private cryptographic keys, and active document contents.
- **Prevention policy:** `Disabled = 1` under
  `HKLM\SOFTWARE\Policies\Microsoft\Windows\Windows Error Reporting` or Policy CSP
  `ErrorReporting/DisableWindowsErrorReporting`.
- **Primary source:** [Microsoft Policy CSP - ErrorReporting](https://learn.microsoft.com/windows/client-management/mdm/policy-csp-errorreporting).

### 2. macOS

#### Quick Look thumbnail cache
- **Artifact:** `/var/folders/../C/com.apple.QuickLook.thumbnailcache/`
  (`index.sqlite` and `thumbnails.data`).
- **Mechanism:** The Quick Look daemon (`quicklookd`) generates and stores
  thumbnails whenever a user previews a file in Finder.
- **Privacy risk:** Previews of files stored on encrypted disk images or
  external drives are cached in cleartext on the main boot APFS volume.
- **Documented purge mechanism:** `qlmanage -r cache` (Apple documented Quick
  Look server cache reset).
- **Primary source:** [Apple Quick Look framework documentation](https://developer.apple.com/documentation/quicklook).

#### Quarantine history (QuarantineEventsV2)
- **Artifact:** `~/Library/Preferences/com.apple.LaunchServices.QuarantineEventsV2`
- **Mechanism:** Apple File Quarantine tracks file provenance for Gatekeeper.
- **Privacy risk:** Permanent SQLite database recording the timestamp, bundle ID,
  exact download URL, and referrer URL for every downloaded file, even from
  private browsing sessions.
- **Documented purge mechanism:** Documented SQLite database deletion and
  recreation, or truncation of `LSQuarantineEvent` rows.
- **Primary source:** [Apple Gatekeeper documentation](https://support.apple.com/guide/security/gatekeeper-and-runtime-protection-sec5599b520d/web).

#### Biome and KnowledgeC pattern-of-life databases
- **Artifact:** `~/Library/Biome/` (macOS 13+) and
  `~/Library/Application Support/Knowledge/knowledgeC.db` (macOS 10.15 to 12).
- **Mechanism:** CoreOS subsystem logging app usage, window switches, Siri
  suggestions, device connections, and website engagement.
- **Privacy risk:** Chronological log of user behavior with sub-second timestamps.
- **Classification:** Audit-only. Internal system framework without a documented
  public mutation API for selective clearing.

#### User diagnostic reports
- **Artifact:** `~/Library/Logs/DiagnosticReports/` (`*.ips`, `*.crash`)
- **Mechanism:** DiagnosticReporter records application crash traces and stacks.
- **Privacy risk:** Crash logs record thread memory, environment variables,
  and loaded shared libraries.
- **Prevention policy:** `DiagnosticMessagesHistory.plist` `AutoSubmit = false`.
- **Documented purge mechanism:** Removal of resolved user reports from the
  diagnostic reports folder.

### 3. Linux

#### FreeDesktop thumbnail cache
- **Artifact:** `~/.cache/thumbnails/` (`normal/`, `large/`, `x-large/`, `fail/`).
- **Mechanism:** FreeDesktop.org thumbnail management standard implemented by
  GNOME Files, Dolphin, Thunar, and PCManFM.
- **Privacy risk:** High-resolution PNG copies of viewed media with MD5 URI
  mapping to the original file path, persisting after file deletion.
- **Documented purge mechanism:** Deletion of cached files exceeding retention
  threshold or desktop cache clear settings.
- **Primary source:** [FreeDesktop Thumbnail Management Standard](https://specifications.freedesktop.org/thumbnail-spec/thumbnail-spec-latest.html).

#### Systemd core dumps
- **Artifact:** `/var/lib/systemd/coredump/` and `~/.local/share/systemd/coredump/`
- **Mechanism:** `systemd-coredump` captures process memory state on SIGSEGV,
  SIGABRT, or crash signals.
- **Privacy risk:** Process heap dumps contain decrypted secrets, database
  connection strings, and memory tokens.
- **Prevention policy:** `/etc/systemd/coredump.conf` (`Storage=none`).
- **Documented vendor mechanism:** `coredumpctl rm` (official systemd API).
- **Primary source:** [systemd-coredump manual](https://manpages.debian.org/testing/systemd-coredump/systemd-coredump.8.en.html).

#### GTK recently used files
- **Artifact:** `~/.local/share/recently-used.xbel`
- **Mechanism:** XML database updated by GTK and Qt file chooser dialogs.
- **Privacy risk:** Detailed history of opened file paths, MIME types, and
  opening application identities.
- **Prevention policy:** `org.gnome.desktop.privacy` `remember-recent-files = false`.
- **Documented vendor mechanism:** `gtk_recent_manager_purge_items()` via
  GNOME Settings "Clear Recent History" interface.
- **Primary source:** [GNOME Privacy Schema](https://github.com/GNOME/gsettings-desktop-schemas).

#### Distribution crash repositories
- **Ubuntu Apport:** `/var/crash/*.crash`
- **Fedora ABRT:** `/var/spool/abrt/`
- **Mechanism:** Distribution-level crash collection daemons.
- **Prevention policy:** `whoopsie` and `abrt-auto-reporting` disabled.
- **Documented vendor mechanism:** `abrt-cli rm` on Fedora, Apport service
  management on Ubuntu.

#### Periodic solid-state TRIM timer
- **Artifact:** `/etc/systemd/system/timers.target.wants/fstrim.timer`
- **Mechanism:** systemd periodic timer issuing TRIM/discard ioctls to SSD storage.
- **Privacy risk:** Storage controllers retain deallocated file sectors in flash
  cells until discard requests are executed.
- **Prevention policy:** Enabling `fstrim.timer`.
- **Documented vendor mechanism:** `systemctl enable --now fstrim.timer` and `fstrim -av`.
- **Primary source:** [fstrim manual](https://manpages.debian.org/testing/util-linux/fstrim.8.en.html).

#### Systemd journal volatile memory storage
- **Artifact:** `/var/log/journal/*`
- **Mechanism:** systemd-journald logs service events, user logins, and kernel traces.
- **Privacy risk:** Detailed session records, executed commands, and process faults
  persist to disk across system reboots.
- **Prevention policy:** `/etc/systemd/journald.conf` (`Storage=volatile`).
- **Documented vendor mechanism:** `journalctl --vacuum-time=0` or `Storage=volatile`.
- **Primary source:** [systemd-journald manual](https://manpages.debian.org/testing/systemd/journald.conf.5.en.html).

### 4. Developer and AI Assistant Residue (Cross-Platform)

#### Local coding assistant session transcripts
- **Artifact:** `~/.codex/sessions/`, `~/.continue/sessions/`,
  `AppData\Roaming\Kiro\User\globalStorage\kiro.kiroagent`
- **Mechanism:** AI coding tools persist full message transcripts, agent
  thoughts, vector indexes, and generated code diffs.
- **Privacy risk:** Plain-text conversation logs frequently contain sensitive
  source code, database connection credentials, API keys, and internal URLs.
- **Documented purge mechanism:** Session pruning by date threshold (e.g.
  removing sessions older than 30 or 60 days) or assistant configuration
  retention limits.

#### Shell command histories
- **Artifacts:**
  - Windows: `%APPDATA%\Microsoft\Windows\PowerShell\PSReadLine\ConsoleHost_history.txt`
  - macOS / Linux: `~/.zsh_history`, `~/.bash_history`
- **Privacy risk:** Accidental entry of passwords, tokens in curl authorization
  headers, and database connection strings.
- **Documented vendor mechanism:**
  - PowerShell: `[Microsoft.PowerShell.PSConsoleReadLine]::ClearHistory()`
  - Bash / Zsh: `history -c`, `history -w`

## Architectural design for `privr purge`

Under decision 13 in `docs/DECISIONS.md`:
- `privr` does not perform unprincipled disk cleaning or arbitrary file deletion.
- It invokes documented vendor erasure actions only.
- Erasure lives behind its own verb (`purge`), never in the default profile,
  never part of `apply`, and never reachable from `--yes`.
- Every purge requires an explicit confirmation flag (`--accept-risk <target>`).
- Every purge writes a transaction journal entry recording that rollback is
  unavailable and why, so a subsequent rollback fails loudly and truthfully.

### CLI command contract

```text
privr purge [--preview] [<target>] [--accept-risk <target>]
```

1. **Default mode (`--preview`):**
   - Read-only audit of residue targets.
   - Measures on-disk footprint in human-readable and versioned JSON formats.
   - Reports whether the generating mechanism is still enabled (identifying
     whether residue will immediately regenerate).
   - Identifies the authoritative vendor clear mechanism.
   - Produces no side effects on the machine.

2. **Execution mode:**
   - Requires explicit target naming and `--accept-risk <target>`.
   - Dispatches only allowlisted, documented platform APIs or verified vendor
     cleaner tools.
   - Verifies the post-state after invocation.
   - Logs the irreversible operation to `privr history`.

### Target taxonomy

| Target ID | Platform | Sensitivity | Vendor interface |
|---|---|---|---|
| `windows.explorer.thumbnail-cache` | Windows | Moderate | Disk Cleanup API (`Thumbnail Cache`) |
| `windows.browser.crashpad` | Windows | High | Crashpad report purge |
| `windows.memory.pagefile` | Windows | High | Security Option (`ClearPageFileAtShutdown`) |
| `windows.storage.trim` | Windows | Moderate | `fsutil behavior set disabledeletenotify 0` |
| `macos.quicklook.cache` | macOS | Moderate | `qlmanage -r cache` |
| `macos.quarantine.events` | macOS | High | QuarantineEvents database truncate |
| `macos.diagnostics.reports` | macOS | High | Diagnostic reports folder purge |
| `linux.systemd.coredump` | Linux | High | `coredumpctl rm` |
